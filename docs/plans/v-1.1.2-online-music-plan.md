# RhythmFlow v1.1.2: online music (Jamendo) plan

Status: **plan only, nothing built yet.** Branch: `v-1.1.2` (from `v-1.1.1`).

Goal: add a second music source, free online music from the Jamendo API, next to
the existing on-device library. The user switches between them with a small
toggle under the "Hi there…" card on For You, and **every tab** (For You, Songs,
Albums, Artists, Playlists) changes to that source. Online is the default.
Country and language are captured at sign-up, detected in the background, and
used to personalise the online content. Every online screen gets a shimmer
skeleton that has the same shape as the real screen while it loads.

> ⚠️ This environment could not reach `api.jamendo.com` or `developer.jamendo.com`
> (blocked by the network policy), so Jamendo specifics below come from the
> public v3.0 API as I know it and are marked **(verify)**. Check them against
> https://developer.jamendo.com/v3.0 before building.

---

## 1. Naming the two sources

The toggle needs two short labels that fit a compact pill and still make sense on
their own.

| Option | Local (on-device) | Online (Jamendo) | Notes |
|---|---|---|---|
| **A (recommended)** | **My Music** | **Discover** | Clear and friendly; "Discover" sets the right expectation (new music, not *your* music) |
| B | Library | Explore | Common in music apps |
| C | Offline | Online | Most literal, but "Offline" sounds like a limitation |
| D | On Device | Jamendo | Literal; uses a brand name in the UI |

Recommendation: **My Music | Discover**, with a small "Powered by Jamendo"
credit inside Discover (Jamendo's terms require attribution **(verify)**).
Icons: `CupertinoIcons.music_albums` / `CupertinoIcons.globe`.
In code: `enum MusicSource { local, online }`.

## 2. What the user sees

### 2.1 Source toggle (For You, right under the "Hi there" card)
- Same style as the bottom tab bar (LiquidGlass background, 0.5 px border, soft
  shadow, `primaryGradient` pill on the selected item, white Poppins label),
  but **compact: ~36.h tall** (bottom bar is 55.h) and full width inside the
  section padding.
- Animated sliding pill (AnimatedAlign, 220 ms, `easeInOutCubic`), light haptic
  on change, same icon and text animation as `_buildTabItem`.
- New reusable widget: `lib/screens/widgets/music_source_switch.dart`.
- The selected source is global and persisted (AppSettingsBloc). The other
  tabs show a small source chip in `CustomTabViewAppBar` (e.g. "🌐 Discover")
  so users always know which world they're in. Tapping it toggles the source.

### 2.2 Tabs per source
| Bottom tab | My Music (unchanged) | Discover (new) |
|---|---|---|
| For You | current screen | **Discover Home**: greeting card + toggle stay; below it: *Top in {country}*, *New releases*, *{language} picks*, *Mood / genre mixes* (chips), *Featured playlists*, *Radio* |
| Songs | local song list | **Online Tracks**: filter chips (Trending · New · genre tags), search, paging list using the same `SongListItem` look, play / like / download (if allowed) |
| Albums | local albums grid | **Online Albums**: same masonry grid & cards (`AlbumArtistPlaylistHelper`), network cover art |
| Artists | local artists grid | **Online Artists**: same cards, follow button |
| Playlists | user playlists | **Online Playlists**: Jamendo featured playlists **+** "Liked online songs" **+** saved Jamendo playlists |

The detail screen (`PlaylistDetailScreen`), mini player, full player, queue and
notification are reused. They gain support for streamed (URL) songs.

Switching source: `AnimatedSwitcher` (fade + slight slide) between the local and
online screen of the current tab. The scroll position of each source is kept.

### 2.3 Minimal, attractive refresh (both sources)
- One section header style everywhere ("Title · count · See all ›").
- Consistent card radii/spacing (reuse the constants in `for_you_screen.dart`).
- Network images through `cached_network_image` (already a dependency) with
  fade-in and a blurred colour placeholder.
- Online-only touches: small "CC" licence badge on now-playing, a "Powered by
  Jamendo" footer on Discover Home.

### 2.4 Loading skeletons (all Discover tabs)
- `skeletonizer` is already a dependency (unused today). It renders the **real
  widget tree** with fake placeholder data as animated shimmer bones, so the
  loading screen has exactly the same shape as the real screen.
- `Skeletonizer(enabled: state.isLoading, effect: ShimmerEffect(baseColor/highlightColor from theme), child: RealScreen(data: isLoading ? Fake.data : real))`
- Per-section skeletons (each Discover Home section loads on its own), plus
  "load more" skeleton rows at the end of paged lists.
- Shared fake data in `lib/screens/online/widgets/skeleton_data.dart`.
- Respect *reduce motion*: static bones when animations are disabled.

### 2.5 Empty, error and offline states
- No internet → banner "You're offline · Showing saved results · Switch to My
  Music" (`connectivity_plus` is already a dependency). Cached content is still shown.
- Section error → small retry card inside the section, not a full-screen error.
- Thin catalogue for a language → fill with global popular tracks, labelled
  "Popular worldwide".

## 3. Country & language

### 3.1 Sign-up (WelcomeScreen)
Add two fields under the nickname, styled like the existing `TextFormField`:
- **Country**: searchable picker (flag + name), stored as ISO-3166 alpha-2 (`IN`).
- **Music language**: searchable multi-select, stored as ISO-639-1 (`ml`, `ta`,
  `hi`, `en`, …). The first one is the primary language.
- Both are pre-filled from background detection and are optional. "Get
  Started" still only needs the nickname.

### 3.2 Background detection (runs as soon as Welcome opens)
1. **Instantly, with no network:** device locale
   (`PlatformDispatcher.instance.locales`) gives language and usually country.
2. **Then, refined:** a lightweight IP-geolocation call (for example
   `ipapi.co/json` or `ipwho.is`, which need no key) to fill or correct the country.
   It has a 3 s timeout and failures are silently ignored. ⚠️ This sends the IP to
   a third party, so mention it in the privacy policy and Play "Data safety"
   form. Alternatively skip IP lookup and use locale only.
3. Fields fill only if the user hasn't typed in them yet.

`LocaleDetectionService` (`lib/utils/services/locale_detection_service.dart`):
pure mapping functions (alpha-2↔alpha-3, language display names) and
injectable HTTP calls, so it can be unit tested.

### 3.3 Existing users (profile already set)
- One-time bottom sheet on first launch of 1.1.2: "Personalise Discover", with the
  two fields pre-filled from detection. Skipping it keeps the detected values.
- Both fields are also added to **Settings → Profile** (`profile_edit_screen.dart`).

### 3.4 How they're used with Jamendo (verify)
- Language → `/tracks?lang=<iso639-1>` (lyrics language filter) and language
  tags/`fuzzytags` as fallback.
- Country → `/artists/locations?location_country=<ISO3166 alpha-3>` gives local
  artists, then their tracks/albums ("Top in India").
- Changing country/language refreshes Discover (cache key includes both).

## 4. Architecture

### 4.1 Settings (AppSettingsBloc, hydrated)
New fields in `AppSettingsState` and `toJson`/`fromJson`:
`musicSource` (default `online`), `country`, `languages` (List),
`localeDetectedAt`, `hasSeenDiscoverOnboarding`.
New events: `updateMusicSource`, `updateRegion(country, languages)`.
`resetToDefaults` keeps country/languages like it keeps the name.

### 4.2 Data layer: `lib/utils/services/jamendo/`
| File | Responsibility |
|---|---|
| `jamendo_config.dart` | base URL `https://api.jamendo.com/v3.0`, `client_id` from `--dart-define=JAMENDO_CLIENT_ID` (never committed), page sizes, TTLs |
| `jamendo_api_client.dart` | `dio` (already a dependency) with interceptors: client_id + `format=json`, timeout, retry with backoff on 5xx/timeouts, `headers.status`/error mapping → typed `JamendoException` |
| `models/jamendo_*_dto.dart` | freezed + json_serializable DTOs: track, album, artist, playlist, radio, paged response (`headers.results_count`, `next`) **(verify field names)** |
| `jamendo_repository.dart` | maps DTOs → app models, pagination, de-duplication, region fallbacks, cache |
| `jamendo_cache.dart` | Hive box `jamendo_cache` (same pattern as `LibraryStorage`): key = endpoint+params+region, TTL (home 6 h, lists 1 h, search 15 min), stale-while-revalidate, offline fallback |

Endpoints used (verify): `/tracks` (`order=popularity_week|releasedate`,
`tags`, `lang`, `search`, `include=musicinfo licenses`, `audioformat=mp32`,
`imagesize`), `/albums`, `/albums/tracks`, `/artists`, `/artists/tracks`,
`/artists/albums`, `/artists/locations`, `/playlists`, `/playlists/tracks`,
`/radios`, `/radios/stream`, `/feeds`.

### 4.3 Models
Reuse the existing models so that cards, lists and the player work unchanged:
- `Song` gets `source` (`local` | `jamendo`), `remoteId`, `streamUrl`,
  `downloadUrl`, `downloadAllowed`, `licenseUrl`, `shareUrl`, `imageUrl`.
  Online songs use IDs like `jm_<id>`, so they never collide with local sha IDs.
- `Album` / `Artist` get `source` + `remoteId` + `imageUrl`.
- New `OnlinePlaylist` (freezed) for Jamendo playlists (not editable).
- **Online songs never go into `MusicState.allSongs`.** Local scans, counts,
  duplicate detection, AI feature extraction and the v1.1.1 library tests stay
  untouched.

### 4.4 Blocs (same structure as `MusicBloc`: bloc / event / state + freezed part files)
| Bloc | Hydrated | Holds |
|---|---|---|
| `DiscoverBloc` | yes (last good home feed) | home sections, each `{status, items, error, fetchedAt}`; events `loadHome({force})`, `refreshSection`, `regionChanged` |
| `OnlineBrowseBloc` (one instance per tab type: tracks/albums/artists/playlists) | no (cache in repo) | filter chips, search query (debounced, restartable), paged items, `hasMore`, `isLoadingMore` |
| `OnlineLibraryBloc` | yes | liked online songs, followed artists, saved albums/playlists, recently played online, download states; this is the **song lookup** for online IDs |

All online blocs use the same concurrency rules as v1.1.1 (coalesce or restart,
never parallel duplicate loads).

### 4.5 Playback (the most delicate part)
Today `AudioService.playSong` requires a local file (`File(path).exists()`),
and `MusicBloc` resolves every queue ID through `state.allSongs`.
Changes:
1. `MusicBloc` gets a single `_resolveSong(id)`: look in `allSongs` first, then
   `OnlineLibraryBloc`/repository cache (injected `SongResolver`). Every
   `firstWhere` on `allSongs` in the playback paths goes through it.
2. `AudioService.playSong`: if `song.source == jamendo`, use
   `AudioSource.uri(streamUrl)`, wrapped in `LockCachingAudioSource` for
   smooth replay, and skip the file-exists check. Errors (404/offline) go to
   the existing invalid-song path.
3. `MediaItem.artUri` uses the network image, so the notification and lock
   screen show cover art.
4. `PlaylistSource` gets `onlineTracks / onlineAlbum / onlineArtist /
   onlinePlaylist / onlineLiked` so shuffle-revert and queue labels work.
5. AI Shuffle needs local audio features, so for online queues it falls back to
   normal shuffle (or orders by Jamendo `musicinfo` tags, speed and vocal, as a
   later phase). The UI shows a hint instead of failing silently.
6. Play counts: online plays go to `OnlineLibraryBloc.recentlyPlayed` and never
   change local stats.

### 4.6 Download to device (only where Jamendo allows it)
- The button is shown only when `downloadAllowed == true` **(verify:
  `audiodownload_allowed`)**.
- dio download with progress → saved via MediaStore into `Music/RhythmFlow/`
  (extend `MainActivity.kt` with `insertAudio`), with ID3 title, artist, album,
  cover and licence URL written.
- v1.1.1's MediaStore observer or rescan then makes it appear in **My Music**
  automatically, with correct album and artist counts.
- Download states live in `OnlineLibraryBloc` (queued, progress, done, failed).

### 4.7 Navigation
`BottomTab._getScreen(index)` reads `musicSource` and returns the local or
online screen for the same index. The route table, tab bar and mini player are
unchanged. Online detail pages reuse `PlaylistDetailScreen` with an online
`PlaylistDetailType`.

## 7. Testing plan
- **Unit:** locale mapping, alpha-2↔3, DTO parsing from recorded JSON
  fixtures, repository mapping/fallbacks/dedup, cache TTL & offline fallback,
  API errors/retries (dio with a fake `HttpClientAdapter`).
- **Bloc:** Discover per-section loading/error/refresh, region change refetch,
  browse paging + debounced search, likes/downloads persistence (hydrated JSON
  round-trip), song resolver (local first, then online).
- **Widget:** toggle switches every tab, skeleton shown then real content,
  offline banner, Welcome fields pre-filled from detection.
- **Regression:** the full v1.1.1 suite (378 tests) must stay green; online
  songs never change local counts.
- **Device checklist:** stream start time, background play and lock screen art,
  airplane-mode behaviour, download appears in My Music.

## 8. Decisions needed before building
1. **Names:** "My Music | Discover" (recommended) or another option from §1.
2. **Jamendo account:** register an app at https://devportal.jamendo.com to get a
   `client_id`. The free tier is for **non-commercial** apps **(verify)**. If
   RhythmFlow will show ads or be paid, a Jamendo commercial licence is needed.
3. **IP-based country detection:** OK to call a third-party geo-IP service
   (privacy policy update), or use the device locale only?
4. **Default source = Discover for everyone**, including existing users with a
   big local library? (Requested: yes. Alternative: Discover for new users,
   keep My Music for existing ones.)
5. **Downloads in 1.1.2** or move them to 1.1.3 to keep this release smaller?
6. **Mixed playlists** (online + local songs in one user playlist): recommended
   **not** in 1.1.2 (keep online favourites separate), possible later.
7. **Network access for development:** this cloud environment needs
   `api.jamendo.com` allowed to test against the live API (otherwise only
   recorded fixtures are used).

## 9. Risks
- Jamendo has a small catalogue for Indian-language music, so language sections
  may be thin. Mitigated by the fallback to "Popular worldwide" and genre mixes.
- API quota/rate limits **(verify)**. Mitigated by caching, a shared cache key per
  region, and no polling.
- The playback refactor touches `MusicBloc`. Mitigated by the resolver
  indirection plus the existing v1.1.1 test suite.
- Store review: streaming plus IP lookup needs an accurate Data safety form.
